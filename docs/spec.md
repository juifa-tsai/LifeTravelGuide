**版本**：1.0  
**編製日期**：2026-11-13  
**旅行日期**：2026-11-15（日）至 2026-11-18（三）  
**部署目標**：GitHub Pages (`https://<username>.github.io/<repo>/`)  
**主要裝置**：iPhone 手機瀏覽器，mobile-first  
**內容語言**：繁體中文為主、保留日文原名  
**資料主檔**：[名古屋四日行程 Excel（Google Drive）](https://docs.google.com/spreadsheets/d/11iKYAKClPwtdG0jtotqcchyyApw57Vbn/edit?usp=drivesdk&ouid=105159926267980667593&rtpof=true&sd=true)

> 本文件供 AI 開發代理直接實作。**不要再以一般偏好問題阻塞開發**；以此規格與 Excel 為準。尚缺資料依「待確認／降級行為」處理，不得自行杜撰店家、座標、營業時間或可食性。

## 1. 產品目標與範圍

建立一個可直接以手機網址開啟的單人名古屋旅行網頁，不需帳號與登入。以六個內容頁面管理四日行程、已收藏地點與旅行文件。

功能優先順序：**可快速確認下一站 → 地圖了解位置 → 展開交通方式 → 開啟 Google Maps → 查看重要文件**。內容簡潔、資訊準確，避免長篇旅遊文字與過多備註。

### 1.1 已確認的需求決策

| 主題 | 決策 |
|---|---|
| 存取 | GitHub Pages 公開靜態網站；點網址即可查看，不做登入 |
| 資料維護 | Git 儲存 JSON，由 AI 協助修改；Excel 作為旅行資料編輯主檔 |
| 地圖 | 嵌入式、淺灰階；行程站點間**示意直線／虛線**，不宣稱實際路徑 |
| 共用標記 | 素食餐廳、咖啡廳、酒吧的**完整收藏清單**在四天地圖皆可顯示，支援分類開關 |
| 圖片 | 合法公開圖源優先，可改為專案內個人照片；無圖則優雅佔位 |
| 文件 | 點擊私人 Google Drive 檔案連結，以使用者 Google 帳號開啟；網站不儲存機票 PDF |
| 離線 | 基本 PWA 離線：已快取的頁面、行程、文字與圖片可看，互動底圖和 Drive 可能不可用 |
| 行程與候選 | **正式行程時間軸**和**候選踩點清單**分開；備選商家不自動插入時間軸 |
| 造訪紀錄 | 踩點清單可勾選已造訪、篩選未造訪；localStorage 保留於本機 |
| 定位 | 點按定位後單次取得位置；不做持續追蹤 |
| 天氣 | 不需要天氣資訊、預報 API 或天氣 UI |
| 交通 | 預設交通方式與估時；點開顯示上下車站、轉乘、步行、預估車資、資訊來源 |
| 名稱 | 繁體中文標題 + 日文原名小字 |
| 時間 | 預計抵達時間＋預估停留分鐘數；僅供彈性參考 |
| 地圖互動 | 點地圖標記捲動至行程卡；點行程卡聚焦地圖並高亮對應標記 |

### 1.2 不在此次範圍

- 不做後台編輯、使用者登入、多人協作或雲端造訪紀錄同步。
- 不做即時運輸導航／列車到站預報／費用即時計算。
- 不購買 Google Maps API、不預設收費地圖服務。
- 不儲存或快取任何機票、訂房 PDF 正本、密碼、訂位 PIN。
- 不自動連接 Google Drive 私有 API 來即時讀取 Excel；改由維護程序輸出靜態 JSON。

## 3. 導航與頁面架構

### 3.1 六個內容路由

```
/#/day/2026-11-15       11/15
/#/day/2026-11-16       11/16
/#/day/2026-11-17       11/17
/#/day/2026-11-18       11/18
/#/places               踩點清單
/#/documents            重要文件
```

使用 `HashRouter`，避免 GitHub Pages 對 SPA 子路徑回傳 404。

**手機導覽**：底部分為「行程｜踩點｜文件」三個主入口；進入行程後，頂部四個日期選項以橫向短標籤切換，實際保有四個獨立路由。這比手機底部放六個擁擠按鈕清楚。桌機可顯示六個完整標籤。日期切換不要重新載入整站。

首頁行為：在日本當地日期 11/15–18 期間，預設開啟當日；行前預設 11/15；行程結束後預設 11/18。使用者上次選擇的日期可儲存在 localStorage，優先於預設日期。若使用 query/hash 直連日期，則以網址為優先。

### 3.2 每日頁布局

由上至下：

1. **精簡頁首**：日期、星期、當天行程主題；不要天氣模組。
2. **互動地圖**：淺灰階底圖（建議 CARTO Positron + Leaflet）；主行程編號標記與虛線；共用 POI 分類切換；定位按鈕。
3. **時間軸**：依時間順序顯示正式安排／餐飲時段區塊；每一站有預計抵達時間、停留時間、圖片、中文與日文名稱、地址、簡短摘要、營業時間（若已核實）、Google Maps 按鈕。
4. **交通連線卡**：緊貼兩個行程卡之間，預設 `地鐵＋步行 · 約30分鐘`；點開後顯示完整路線、站名／線名、轉乘、步行段、預估車資、資料來源。尚未核實之數值顯示「約」或「待確認」，不可填入虛構車資。
5. **必要的日末操作**：如返回飯店之 Google Maps 連結，可放在最後一個行程站。

行程區塊文案以「一句重點」為限，重要警示（如末點餐時間、機票時間）在必要時以小字保留。照片為 16:9 或 4:3 的裁切、統一圓角。不設冗長遊記。

### 3.3 地圖行為

- Map 位置在每日頁**時間軸之前**；手機地圖高度約 `min(42vh, 360px)`，最小 250px。
- 使用 `Leaflet` 搭配授權允許的灰階底圖供應商；**務必保留 OpenStreetMap／底圖來源 attribution**。
- 正式點位顯示 `1, 2, 3…` 的小編號標記（不把無座標、同一地點重複事件、跨國航班當成有效地理新點）。相鄰有效站點用細虛線／半透明線連接；**僅示意方向，不代表實際行車線路**。
- 對飛航段 `TPE → NGO` 不畫跨國連線；不連接「午餐待選」這類無實際座標的虛擬地點。不得跳過未知地點後宣稱該線段為真實轉乘。
- 在四天地圖都顯示完整的共用收藏點圖層，提供三個獨立開關：**素食、咖啡、酒吧**；互不影響。地圖初始視野以當天正式行程在名古屋的有效站點為準，避免共用點或遠距機場過度縮小視角；另提供「全部顯示」／「回到當日行程」視野操作。
- 不同圖層以低飽和色與形狀區分：正式行程深青、素食橄欖綠、咖啡暖褐、酒吧暗莓色；保留簡潔。
- 點正式地圖 pin：高亮 pin，捲動至對應行程卡，短暫突出卡片邊框。
- 點正式行程卡：地圖 `panTo`／`flyTo` 該 pin，並高亮；即使地圖已捲離視窗，也應有小型「在地圖查看」按鈕便於返回地圖。
- 點共用收藏 pin：先顯示簡短 popup（名稱／分類／照片縮圖／Google Maps 連結）；不因其為候選而改動正式時間軸。
- 定位按鈕調用 `navigator.geolocation.getCurrentPosition`；明示瀏覽器授權，僅單次定位，不使用 `watchPosition`、不在伺服器傳送／儲存定位。拒絕權限時提示可自行在地圖瀏覽。
- 外部地圖開啟 `https://www.google.com/maps/search/?api=1&query=...`；交通導航可按 From/To 使用 Google Maps Directions URL。`target="_blank"` + `rel="noopener noreferrer"`。
- 地理座標是**實作前必要資料**；若 Excel 未有座標，必須先可靠地理編碼並核對，**不能猜測**；尚未解決的點只列於時間軸／清單，不在地圖放 pin。

### 3.4 踩點清單（`/places`）

單頁分類篩選：老件店、古蹟／歷史、美術館／公園、素食餐廳、咖啡廳、酒吧、住宿、交通。可多選，支援「全部／未造訪／已造訪」與簡易關鍵字搜尋。

每一列卡片包含：照片、中文名與日文名、分類、地址、營業時間（若已核實）、50 字以內介紹、Google Maps 連結、已造訪 checkbox。點選已造訪後當場更新，並存於本機 `localStorage`，鍵用穩定 `place_id`；重整頁面仍保留，清除瀏覽器資料則可能消失。沒有雲端帳號或同步。可提供「清除全部勾選」二次確認，非必要 P0。

不得將「已造訪」狀態寫回 Excel 或公開 JSON，也不要用「已造訪」改變正式日程順序。

### 3.5 重要文件（`/documents`）

使用圖示與短按鈕卡片分組：機票、住宿、接駁、交通地圖。從 Excel `04_重要文件` 讀取按鈕名稱與連結，包括：

- 機票電子行程單（中英版）、機票確認信。
- 住宿入住憑證、飯店訂單資料。
- 11/15 機場專車接機憑證。
- 名古屋市營地下鐵官方路線圖、名鐵往返機場官方資訊。

**安全要求**：GitHub Pages 是公開網站，JSON 裡的 Drive **檔案 URL／ID 也會公開可見**；僅依 Google Drive 原有「私人」權限限制檔案內容讀取。網頁內不可寫入 PIN、訂單完整編號、票號、出生日期、電子郵件、信用卡資訊等敏感資料。不可用 iframe 或後端代理公開私人文件。若使用者日後不希望外界看到檔案 URL，須改為登入後取得連結的方案，此版不實作。

外部 Google Drive 連結由使用者登入自己的 Google 帳號開啟；若權限不足或無網路，瀏覽器可能無法開啟文件。文件連結不得預先快取／保存 PDF 正本。未有連結的文件項目不顯示灰色假按鈕。

## 4. 視覺設計系統

風格：**輕鬆、安靜、旅行筆記感、清爽留白**。不使用高對比觀光海報色，也不要大面積彩色卡片或複雜陰影。

建議色票（非品牌強制）：

| Token | Color | 用途 |
|---|---|---|
| `--bg` | `#F7F8F6` | 頁面暖灰白背景 |
| `--surface` | `#FFFFFF` | 卡片 |
| `--text` | `#273330` | 主要文字 |
| `--muted` | `#6E7C78` | 次要文字 |
| `--primary` | `#3F7773` | 選取、正式行程、按鈕 |
| `--border` | `#E3E9E6` | 細分隔線 |
| `--vegan` | `#81916F` | 素食 POI |
| `--coffee` | `#AA8B70` | 咖啡 POI |
| `--bar` | `#9A7889` | 酒吧 POI |

排版：系統字體 `-apple-system`, `BlinkMacSystemFont`, `Noto Sans TC`, `Noto Sans JP`, sans-serif。主要標題 20–24px、卡片標題 16–18px、內容 14–15px、日文次要資訊 12–13px；行高約 1.4–1.6。卡片圓角 14–16px，細邊框，陰影極淡；點擊區高度至少 44px。

**手機優先**：iPhone 約 375–430px 寬仍須可單手操作，不橫向溢出。底部導覽需避開 iOS safe area（`env(safe-area-inset-bottom)`），時間軸右側照片不可讓中文與日文名稱截斷到難讀；有必要使用 2 行 ellipsis。

## 5. 資料模型與 Excel 對應

### 5.1 Excel 頁籤為唯一內容主檔

| Excel 分頁 | 用途 | 前端輸出 |
|---|---|---|
| `00_旅程總覽` | 航班、住宿、旅遊日程摘要、飲食偏好 | `trip.json` |
| `01_每日行程` | 各日站點、順序、抵達時間、停留、類型與狀態 | `itinerary.json` |
| `02_踩點清單` | 所有地點及 POI 分類、地址、日文名稱、來源／圖片／座標欄 | `places.json` |
| `03_交通銜接` | 起終點 ID、方式、摘要、詳細路線與估時 | `legs.json` |
| `04_重要文件` | 文件標題、私人 Drive 連結、地鐵／機場官方資訊 | `documents.json` |
| `05_待確認` | 缺漏座標、圖片、飲食或營業日核對任務 | 開發檢查報告（不上線） |
| `06_資料字典` | 主鍵、欄位、驗證規則與注意事項 | 匯入腳本／JSON schema |

### 5.2 範例 JSON 結構

建議建立自動匯入腳本 `scripts/xlsx-to-json.ts` 或 Python 程式（執行於開發機／CI，**不在瀏覽器直接讀私人 Google Drive**），以 Excel 工作簿輸出靜態 JSON。範例：

```json
{
  "places": [
    {
      "id": "art_museum",
      "category": "美術館",
      "nameZh": "名古屋市美術館",
      "nameJa": "名古屋市美術館",
      "address": "2 Chome-17-25 Sakae, Naka Ward, Nagoya, Aichi, Japan",
      "lat": null,
      "lng": null,
      "imageUrl": null,
      "imageAttribution": null,
      "mapsUrl": "https://www.google.com/maps/search/?api=1&query=...",
      "hoursText": "09:30–17:00",
      "verified": true
    }
  ],
  "itinerary": [
    {
      "date": "2026-11-17",
      "sequence": 3,
      "placeId": "art_museum",
      "arrivalTime": "10:15",
      "stayMinutes": 110,
      "displayStatus": "正式行程",
      "summary": "梵谷《吊橋》印象派特展"
    }
  ],
  "legs": [
    {
      "date": "2026-11-17",
      "fromPlaceId": "shrub",
      "toPlaceId": "art_museum",
      "mode": "步行",
      "summary": "約15–20分鐘",
      "minutesEstimate": 18,
      "details": "錦2丁目 → 白川公園美術館",
      "fareJpyEstimate": null,
      "certainty": "估算"
    }
  ]
}
```

實作需要校正示例 JSON 裡的 `mapsUrl` 為 Excel 的**完整連結**，不可保留 `...` 佔位。示例 `lat`／`lng` 為 `null`，意指尚未核對座標，並非地理點位 (0,0)。

欄位驗證：

- `place.id` 唯一；`itinerary.placeId` 與 `legs.*PlaceId` 全部須能參照 `places`。
- `date` 為 `YYYY-MM-DD`；每日 `sequence` 正整數、唯一，依序顯示；`arrivalTime` 為 `HH:mm`。
- 所有分鐘值與車資以 number/null 型別保存；估時不代表驗證的營運時刻。
- 站點僅有「候選／備選」且不存在於每日行程時，僅出現在共用地圖候選圖層／踩點清單。**虛擬餐時區塊**（例如 `meal_tbd_17`）可在時間軸，但無 pin。
- 不在 JSON 中暴露票號、PIN、預訂聯絡方式、私人地址／電子郵件等敏感欄位。
- `imageUrl` 缺失使用前端預設佔位圖；遠端圖像需合法授權且允許連結，勿直接抓取 Google Maps／Google 評論照片轉存。

### 5.3 Excel → GitHub 更新流程

1. 在 Google Drive 編輯 Excel，保留所有工作表、表頭及 `place_id`。
2. 將更新後 Excel 下載至開發專案（或 AI 開發環境）。
3. 執行匯入腳本產生四天行程及 POI／文件 JSON。
4. 進行靜態驗證（ID、日期、URL、敏感資料、時間欄位、座標）。
5. 提交 Git commit → GitHub Pages 自動發布。

**不宣稱 GitHub Pages 可直接同步使用者私人 Excel**。如後續需要自動同步，另建立 GitHub Actions 和受保護的 Google Drive 認證流程；不可將憑證放進公開前端程式碼。

### 6.1 時區

- 日本境內所有排程、到店與營業時間以 `Asia/Tokyo`（JST, UTC+9）呈現。
- 桃園機場航班出發／抵達時間以 `Asia/Taipei`（UTC+8）呈現，旁邊標註「台灣時間」，不能用相同時區直接相減。
- 預設日頁選擇以**名古屋日期**為準，而非使用者旅行前在台灣的本地日期。

### 6.2 基本離線模式

- App Shell、CSS、JS、JSON 在首次成功開啟後可離線使用。
- 遠端圖片採 runtime cache（只在符合授權及 CORS 的情況），保留載入失敗佔位。
- 地圖圖磚不保證離線；無網時顯示中性底圖佔位與文字站點順序、交通連線、Google Maps 按鈕不可用的提示。
- 不離線保存 Google Drive PDF 或任何私人憑證；外部連結仍需網路及登入。
- PWA 可「加入主畫面」；優先實作快取正確性與更新，不強制做推播。
- 新版本發布要更新快取，使四天行程修改能反映；不得一直顯示舊資料。

## 7. 錯誤狀態與安全

- 若資料 JSON 載入失敗，顯示「行程資料暫時無法載入」和「重新整理」，不是白畫面。
- 若 `placeId` 不存在，該站保留時間摘要並標示資訊待補，不讓整頁崩潰。
- 若圖片 403/404，使用統一漸層或圖示佔位，卡片保持高度穩定。
- 若座標缺漏，跳過地圖標記，但保留文本與 Google Maps 連結。
- 若定位遭拒絕或逾時，提示後仍可操作地圖；不得要求永久授權。
- 若某天只有機場和飛行事件，地圖仍需可呈現其他名古屋境內點位，不要自動拉到台灣與名古屋的跨國範圍。
- 禁止在 public JSON、HTML、JavaScript、console log、GitHub commit 中存放預訂 PIN、訂單號、電子機票票號、信用卡、個人信箱等資訊。
- Google Drive 文件保持原有權限，不修改成「知道連結的任何人均可查看」。
